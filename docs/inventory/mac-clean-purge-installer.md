# Mole macOS inventory: `mo clean`, `mo purge`, `mo installer`

Source: tw93/Mole `main` @ 5dd93fe3, VERSION 1.72.0 (`mole:115`), repo `../mole`. Read-only research. Every `file:line` is relative to the repo root. "Inferred" = read from code, not executed. "Not implemented" = documented or implied but absent in code.

Global facts that apply to every row:
- All three commands refuse to run as root: `Run Mole without sudo; it requests administrator access when needed.` exit 1 (`bin/clean.sh:8-13`, `bin/purge.sh:7-12`, `bin/installer.sh:5-9`, `mole:10-13`).
- `--debug` is stripped by the dispatcher and exported as `MO_DEBUG=1` before the sub-script runs (`mole:77-92,320`).
- Dispatcher routes `mo clean|purge|installer` to `bin/*.sh` via `run_mole_command` (`mole:329-346`). Interactive `mo` menu item 1 "Clean" (also key `1`) launches clean (`mole:186,264,271`). Purge and installer are CLI-only; they are not in the interactive menu (`mole:186-190`).
- Deletion is permanent (`rm -rf`) for clean, purge, installer. Trash is not used (README:158; `lib/core/file_ops.sh:1816-1818` for clean/purge; installer calls `mole_delete` with default `MOLE_DELETE_MODE=permanent`, `file_ops.sh:2386,2406`). Trash is only used by uninstall/analyze/slim.
- No JSON output exists for these three commands. `--json` exists only for `analyze`, `status`, `history` (`bin/completion.sh:21-22`). Documented-but-not-implemented: none found for JSON; the README only claims JSON for the other commands (README:341-347).

## 7. Porting notes (subtle, easy to get wrong)

1. Delete is permanent, not Trash, for all three commands. Clean empties `~/.Trash` itself by permanent delete of each top-level child. Mole's only Trash path (`mole_delete` mode trash, Finder/`trash`) belongs to uninstall. A friendly Rust tool should decide this explicitly and probably offer Trash for installers and purge.
2. Size accounting (clean): bytes come from a Perl `lstat` walk counting allocated blocks (`st_blocks*512`), hardlinks counted only when all links lie inside the tree, no symlink following, no crossing devices, and on Darwin `getattrlist` PRIVATESIZE to avoid counting APFS cloned/shared extents (`bin/clean.sh:747-796`). Size and delete counts are measured before the delete; summary adds only items actually removed. Unmeasured items keep their row with `+`/"unknown" (never 0B). Purge uses `du -skP` (different semantics, estimate). Installer uses `stat -f%z` apparent bytes. Sections overlap on purpose (User essentials sweeps whole `Caches/*`, later sections list sub-paths): dry-run dedups by path identity and charges descendants to the measured ancestor (`bin/clean.sh:279-437`).
3. Sudo: tool never runs as root. System section is separate and gated on `SYSTEM_CLEAN`. Ask once, up front, with a one-keystroke prompt that accepts a typed password; Space skips. A keepalive process refreshes the credential; `sudo -n` is used for non-interactive probes, never a password prompt mid-run. Dry-run never prompts. Preview as root is split from the user write path (#1210). Touch ID is configured separately (`mo touchid`).
4. Timeouts everywhere: every external command goes through `run_with_timeout` with a named bucket (2/3/5/10/20/30/15 s); section-level budgets (system 120 s, cloud/office 300 s, container caches 120 s, orphan services 60 s, orphan age walk 60 s); a timed-out scan result is discarded whole, never used as a delete plan ("partial prefix is not a safe deletion plan", `caches.sh:90-100`). Timeout means skip with a visible note; signals (>=128) abort the whole run; exit 124 is "timeout".
5. Fail closed: unknown process state, unreadable plist, missing perl, failed `lsof`, failed `tmutil status`, unavailable `codesign` all mean keep. Examples: Software Update probe treats unreadable plist as pending (macOS 27 beta bricking incident, `system.sh:58-87`), TM status unknown = skip, whitelist unreadable = abort.
6. TOCTOU rechecks at the delete sink: dev/inode/mtime identity (`_mole_snapshot_path_identity`, `_mole_path_matches_identity`), parent identity, re-run of the eligibility predicate right before `rm`, `safe_remove` final guard callbacks (`_MOLE_SAFE_REMOVE_FINAL_GUARD`). Port as "plan then verify identity at delete".
7. Symlinks: `validate_path_for_deletion` refuses relative paths, `..` components, control characters, a symlink whose resolved target is a critical path, and any path with a symlinked ancestor (`file_ops.sh:1160-1260`); critical roots (`/`, `/System`, `/usr`, `/Library`, `/Applications`, `/Users/<name>`, `/private/var/db`...) and case-alias spellings of them are refused (`file_ops.sh:1044-1135`). Installer skips symlink files. Purge compares physical paths for containment and re-resolves at the sink. Orphan cleanup and external volume refuse symlinked roots.
8. Live-owner checks: a cache is skipped when its owner app is running or any process holds an open handle (`lsof` complete view), SQLite WAL/shm families are protected while in use, Chromium caches are cleaned only if the browser is not running and re-checked after sizing (Chrome Google dir excluded from the generic sweep). Do not delete live caches even if old.
9. Path protection data (`app_protection_data.sh`, `app_protection.sh:406-700`) is a large allowlist of "never touch" bundle ids and paths (input methods, keychains, Steam libraries, OrbStack, compiled ML models). Mole cleans by walking known roots and per-app rules, not by pattern-matching "looks like cache". Expect most of the work to be curated data, with a regression test per incident.
10. Age rules differ per target and are not uniform: 7 d temp/log/crash/purge, 14 d macOS installer apps, 30 d orphans/Mail/memory reports/saved state, 1 d GPU caches, 1 h idle-asset downloads, 48 h TM, keep-N-newest for Xcode DeviceSupport (2) and AI agent versions (1 + active).
11. Native owner commands over rm: npm/pip/uv/pnpm/bun/corepack/mise/go/docker/brew/nix/tmutil/simctl run their own cleanup; Mole measures the root before and after and reports the delta (`dev.sh:51-160`). Docker only against a local endpoint. `brew cleanup --prune=30` throttled to once per 7 days; `brew autoremove` is preview-only.
12. Purge and clean share target knowledge but differ in policy: clean's `clean_project_caches` removes `.next/cache`, `__pycache__`, `.dart_tool` only when git tracks nothing there; purge covers 33 names but requires git-untracked, not-in-use, 7 d idle. Never delete `target/deploy` keypairs, `vendor` that is not Composer, `bin` that is not .NET, `node_modules` whose install marker is older than the newest file.
13. `--dry-run` must exercise the same eligibility code as the real run (several bugs came from divergence, #1390/#1391); the preview file doubles as the whitelist authoring aid.
14. Non-interactive behaviors differ per command: clean runs unattended without confirmation (user-level only unless sudo cached), purge refuses without `--yes` and exits 0 on refusal, installer has no non-interactive path (needs tty selection) and no `--yes`.
15. Platform-specific bits to replace on Windows/Linux: everything under `~/Library/*`, `/Library/*`, `/private/var/*`, `tmutil`, `codesign`, `mdfind`, `plutil`, Darwin user dir, TCC/Full Disk Access, APFS snapshots, `diskutil`. Portable core: age/identity/process guards, project-artifact purge (only the `.dataless` and `Library` prune are mac-only), installer extension search (replace paths and Mail/Telegram locations).
16. Documented but not implemented / mismatches seen: README claims were cross-checked only for purge, installer, safety and JSON; confirmed mismatches are (a) `mo installer -n` accepted but absent from `--help` (`installer.sh:1005`, `help.sh:15-24`); (b) installer has no entry in `bin/completion.sh` option words (only clean and purge have per-command words, `completion.sh:20,23`; fish/zsh/bash emit blocks only for those, e.g. `completion.sh:40-56,401-429`), so `mo installer --dry-run` is not tab-completed (inferred from grep); (c) `mo clean --select/--categories/--exclude` are documented-as-removed and return an error.
