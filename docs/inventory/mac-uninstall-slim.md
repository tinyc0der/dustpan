# Mole macOS: `mo uninstall` and `mo slim` feature inventory

Source: tw93/Mole, branch main, SHA 5dd93fe3, repo `../mole`, `VERSION="1.72.0"` (`mole:115`). All paths below are relative to that repo. "Documented but not implemented" items are tagged **[DOC-ONLY]**. Shell-implementation quirks that a port must not copy are tagged **[QUIRK]**.

## 0. Entry points, global flags, completion

- Dispatcher routes `uninstall` to `bin/uninstall.sh` and `slim` to `bin/slim.sh` with remaining args (`mole:332-333`, `mole:347-348`). Command list entries: `uninstall:Remove apps completely`, `slim:Remove Intel code from universal apps` (`lib/core/commands.sh:6,13`). Main interactive menu entry 2 launches uninstall (`mole:187`, `mole:265`, `mole:275`).
- `--debug` is stripped by the dispatcher before dispatch and exported as `MO_DEBUG=1` (`mole:77-92`, `mole:300-303`). Both scripts also accept `--debug` themselves (`bin/uninstall.sh:2111`, `bin/slim.sh:852`).
- `bin/completion.sh` has per-command flag lists only for `clean`, `analyze`, `history`, `purge` (`bin/completion.sh:20-23`). **No uninstall or slim flag completion exists**; only the subcommand names come from `MOLE_COMMANDS` (`bin/completion.sh:14-18`).
- Both commands refuse to run as root: uninstall `bin/uninstall.sh:10-13`, slim `bin/slim.sh:10-13`. Admin rights are requested per operation instead.
- Both set `LC_ALL=C LANG=C` (uninstall saves the user's locale first for display-name lookup: `bin/uninstall.sh:16-21`; slim `bin/slim.sh:19-20`).

## 2. Uninstall in depth

### 2.1 App discovery and metadata

**Search roots** (`uninstall_print_app_search_dirs`, `bin/uninstall.sh:532-562`): `/Applications`, `~/Applications`, `/Library/Input Methods`, `~/Library/Input Methods`, the PlayCover Applications dir if it exists, and every `/Volumes/*/Applications` that is readable and is not the same inode as `/Applications` or `~/Applications` (`-ef` compare).

**Walk** (`bin/uninstall.sh:757`): `find <root> -mindepth 1 -maxdepth 3 -iname '*.app'`, so Setapp (`/Applications/Setapp/X.app`) and vendor sub-folders are found by depth, not by a dedicated provider. Hidden folders are pruned unless the folder is itself a `.app` (updater staging copies like `/Applications/.x-update/app/X.app` are not installs; a hidden `.app` is still listed). Foundation's "(A Document Being Saved By ...)" replacement folders are pruned using localized names read from `Foundation.framework/Resources/Document.loctable` (`bin/uninstall.sh:690-756`).

**Per-path skips** (`uninstall_should_skip_app_path`, `bin/uninstall.sh:564-601`): missing path; a `.app` nested inside another `.app` (case-insensitive); PlayCover launcher alias folders; symlinks whose target resolves into `/System`, `/usr/bin`, `/usr/lib`, `/bin`, `/sbin`, `/private/etc`.

**pkgutil receipts** (non-standard install locations): `pkg_receipt_nonstandard_app_paths` walks `pkgutil --pkgs` (skipping `com.apple.*`) then `pkgutil --files <id>`, keeps `.app` bundles under `/usr/local/*` and `/opt/*` that exist now (`lib/core/pkg_receipts.sh:12-234`). Receipt list is the cache key; cache file `~/.cache/mole/pkg_receipt_apps_v1`, TTL 3600 s, 604800 s when a receipt-plist mtime stamp is available (`lib/core/pkg_receipts.sh:19-44`). Scan has an 8 s budget (`MOLE_PKG_RECEIPT_SCAN_TIMEOUT`, `lib/core/pkg_receipts.sh:100-104`). Added to discovery at `bin/uninstall.sh:925-949`.

**Homebrew casks**: not a discovery source. Casks are found because their `.app` is symlinked or copied into the roots above. Cask ownership is detected per app (see 2.7).

**Setapp, App Store**: no dedicated discovery or source label, and README claims none. Setapp's `~/Library/Application Support/Setapp/Applications` appears only as a sibling-scan root (`lib/uninstall/batch.sh:1081-1091`). App Store apps (`_MASReceipt`) are listed and removable like any other; `_MASReceipt` is checked only by slim (`bin/slim.sh:151`). `com.setapp.DesktopClient` is in a protected-data list (`lib/core/app_protection_data.sh:639`).

**Bundle id** (`uninstall_resolve_bundle_id`, `bin/uninstall.sh:603-630`): `CFBundleIdentifier` via `plutil -extract`; falls back to cached id, else the literal `unknown`. Pipes and control chars are stripped because rows are pipe-delimited.

**Display name** (`uninstall_resolve_display_name`, `bin/uninstall.sh:225-305`): first the bundle's own localized `InfoPlist.strings` for the user's first-localized language from `defaults read -g AppleLanguages`, matching `zh-Hans-CN` against `zh-Hans`, `zh_CN`, `zh` lproj spellings and `Base.lproj` (`bin/uninstall.sh:125-223`); never falls through into a language the user did not ask for (MiaoYan case). Then `mdls kMDItemDisplayName` (0.04 s budget; paths and dot-names rejected), then `CFBundleDisplayName`, then `CFBundleName`. Versioned bundle names are kept when metadata collapses distinct installs (`bin/uninstall.sh:292-299`). `.app` suffix, `|` and tabs/newlines stripped.

**Size**: first `mdls kMDItemPhysicalSize` (0.04 s budget), then bounded `du -skP` (2 s) only when cold rows <= 20 (`bin/uninstall.sh:84-123`, `bin/uninstall.sh:1141-1148`, constants `bin/uninstall.sh:47-55`); a deferred background refresh fills real `get_path_size_kb` values into the cache (`bin/uninstall.sh:367-530`). Size is not measured for app data under `~/Library/Containers` or `Group Containers` without Full Disk Access (`lib/core/file_ops.sh:4217-4226`). Shown as `--` in the selector when unknown, `N/A` in list/summary (`bin/uninstall.sh:57-71`, `lib/ui/app_selector.sh:29-34`). Units are decimal: GB/MB/KB at 1000-multiples (`bin/uninstall.sh:1332-1349`).

**Last used**: `mdls kMDItemLastUsedDate` (0.2 s), parsed with `date -j -f "%Y-%m-%d %H:%M:%S %z"`; values before epoch floor 978307200 (2001-01-01) are dropped; if absent, falls back to the app's directory mtime if after the floor (`bin/uninstall.sh:46,424-431,1413-1419`). Rendered as `Today`, `Yesterday`, `N days ago`, `N week(s) ago`, `N month(s) ago` (30-day months), `N year(s) ago` (365-day), else `Unknown` (`bin/uninstall.sh:1350-1377`). Selector truncates to 9 columns (`lib/ui/app_selector.sh:23-25`).

**Source column**: the TUI shows no source column. The preview shows a `[Brew]` tag next to the app (`lib/uninstall/batch.sh:2432-2445`). JSON/`--list` has `"source": "Homebrew"` or `"App"` (`bin/uninstall.sh:2002-2003`). No "Setapp" or "App Store" value exists.

**Dedupe** (`_scan_dedupe_bundle_ids`, `bin/uninstall.sh:1202-1281`): key is `bundle_id|basename.app`, so Xcode.app and Xcode-beta.app (same id) both survive, but mirrored clones collapse. Rank order: `/Applications` (1) < `~/Applications` (2) < other (3) < `/Volumes` (4). A hidden `.x.app` folds into a visible app with the same id. Rows with id `unknown` are never merged.

**Cache**: metadata cache `~/.cache/mole/uninstall_app_metadata_v5` with fields `path|mtime|size_kb|last_used_epoch|updated_epoch|bundle_id|display_name|language_signature`, lock dir `<file>.lock` (5-minute stale break), TTL 7 days, language signature = `cksum` of the language list (`bin/uninstall.sh:42-46,169,307-340,1293-1480`). A row is a warm hit only if mtime matches and size, name, bundle id and language signature are all valid (`bin/uninstall.sh:1013`). In one interactive session the app list is reused when the live inventory only lost rows (`bin/uninstall.sh:852-875`, `bin/uninstall.sh:2232-2240`).

### 2.2 What leftovers are matched

All user-level candidates come from `find_app_files <bundle_id> <app_name> <app_path>` (`lib/core/app_protection.sh:1334-2216`). `app_name` is the **current bundle basename** (not the cached display name), by design (`lib/uninstall/batch.sh:2024-2028`). Candidates must exist.

By display name (requires name length >= 2; `lib/core/app_protection.sh:1385-1419`): under `~/Library`: Application Support, Caches, Logs, Preferences (dir and `.plist`), Saved Application State `.savedState`, Services `.workflow`, QuickLook `.qlgenerator`, Internet Plug-Ins `.plugin`, Audio Plug-Ins (Components, VST, VST3, Digidesign), PreferencePanes, Input Methods `.app`, Screen Savers, Frameworks, Contextual Menu Items, Spotlight `.mdimporter`, ColorPickers, Workflows, Address Book Plug-Ins, Accessibility, Mail Bundles; plus `~/.config/<name>`, `~/.cache/<name>` and lowercase, `~/.local/share/<name>`. Name variants when the name has spaces: no-space, underscore, hyphen, lowercase forms (`lib/core/app_protection.sh:1511-1540`, issue #377). Base-name variants after stripping channel suffix (`Nightly|Beta|Alpha|Dev|Canary|Preview|Insider|Edge|Stable|Release|RC|LTS|Developer Edition|Technology Preview`) (`lib/core/app_protection.sh:1363-1368,1542-1557`). Product-leaf variants from the bundle id leaf only if it extends the display name at a camel/digit boundary, >= 8 chars (`lib/core/app_protection.sh:1486-1526`). Crash/updater leaves `Caches/SentryCrash/<name>`, `KSCrash/<name>`, `<variant>-updater` (skipped for common names and `electron`) (`lib/core/app_protection.sh:1469-1485`).

By bundle id (only when it passes the reverse-DNS regex; `lib/core/app_protection.sh:1420-1456`): Application Support, Caches, Logs, Saved Application State, Containers, WebKit (and `com.apple.WebKit.WebContent/<id>`), HTTPStorages (+`.binarycookies`), Cookies, Application Scripts, Input Methods, Autosave Information, SyncedPreferences, `Caches/<id>.ShipIt`, PLCrashReporter/Crashlytics/Bugsnag per-id folders, the per-user Darwin cache root `/private/var/folders/.../C/<id>` via `mole_darwin_user_cache_root`. Preferences `<id>.plist`, `Preferences/<id>`, ByHost `<id>.*.plist` at a dot boundary (`lib/core/app_protection.sh:1648-1673`). nsurlsessiond download cache. Group Containers whose name has the bundle id at a boundary (`lib/core/app_protection.sh:1675-1691`). Derived roots (Application Scripts, Containers, `Application Support/FileProvider`) with name containing the id at a boundary, covering share extensions and file providers (`lib/core/app_protection.sh:1693-1724`). UUID-named containers are included only if `.com.apple.containermanagerd.metadata.plist` `MCMMetadataIdentifier` equals the bundle id (`lib/core/app_protection.sh:1098-1111,1727-1748`). `com.apple.sharedfilelist/...ApplicationRecentDocuments/<id>.sfl2|sfl3|sfl4` (`lib/core/app_protection.sh:1778-1796`).

Embedded helpers (`lib/core/app_protection.sh:1142-1204`, use at `1798-1840`): up to 128 `Info.plist` under the bundle (`xpc`, `appex`, and `.app` only inside `Contents/Library/LoginItems`), skipping Sparkle ids; their ids map to exact `~/Library` paths (Application Scripts, FileProvider, Caches, Containers, HTTPStorages, Preferences, WebKit, ByHost).

Launch agents (`~/Library/LaunchAgents`, `lib/core/app_protection.sh:1842-1905`): candidates are plists named `<id>.plist` / `<id>.*.plist`, or containing the display name (name search only if length >= 5 and not in `LAUNCH_AGENT_NAME_COMMON_WORDS`, `lib/core/app_protection_data.sh:644-650`). Every candidate must pass the ownership test below.

Native messaging hosts: `~/Library/Application Support/*/NativeMessagingHosts/*.json` and one level deeper, owned only if the manifest `path` resolves inside the app bundle, file <= 64 KiB (`lib/core/app_protection.sh:1113-1141,1750-1774`).

Vendor-nested folders, e.g. `Application Support/Avid/Sibelius`, only when the vendor token comes from the bundle id (`lib/core/app_protection.sh:907-960,1642-1660`).

Diagnostic reports: `~/Library/Logs/DiagnosticReports` files prefixed by `CFBundleExecutable` (or no-space name) and `<prefix> Helper`; Electron executable name is not used (`lib/core/app_protection.sh:2218-2286`; called `lib/uninstall/batch.sh:2289-2303`). Skipped under sibling guard.

Toolchain heuristics, regenerable data only, skipped when a sibling survives (`lib/core/app_protection.sh:1960-2215`): DevEco, Android Studio (`~/.android/cache|build-cache|breakpad`, `Application Support/Google/AndroidStudio*`), Xcode (DerivedData, all `*DeviceSupport`, `CoreSimulator/Caches`, `~/.Xcode`), JetBrains versioned folders (using `idea.paths.selector`), Godot, Docker (caches only; `~/.docker` auth kept), Maestro Studio, Anki, Raycast. Also a Zed channel HTTPStorages rule (#422) (`lib/core/app_protection.sh:1562-1575`).

System-level, **review only** (`find_app_system_files`, `lib/core/app_protection.sh:2288-2570`): `/Library/{Application Support,Caches,Logs,Preferences,Frameworks,Internet Plug-Ins,Input Methods,Audio/Plug-Ins/*,QuickLook,PreferencePanes,Screen Savers,Extensions/*.kext,StartupItems}` by name/id, `/Library/LaunchAgents|LaunchDaemons` by `<id>.plist`, `<id>.*.plist`, and by name (>= 5 chars, not common words, not `com.apple.*`), `/Library/PrivilegedHelperTools` by id boundary and by lowercase name variants (>= 5 chars, non-common), `/private/var/db/receipts` by id boundary, `/Users/Shared` vendor paths, and BOM receipts: `lsbom -f -s` on `/private/var/db/receipts/*.bom` matched to the bundle id, keeping payload paths only if allowlisted (LaunchAgents/Daemons by id, PrivilegedHelperTools by id, receipts) (`lib/core/app_protection.sh:2575-2712`). **Receipts feed only the review-only list.**

Not matched: team id (no Team ID based leftover matching anywhere in uninstall; `TeamIdentifier` is read only by slim, `bin/slim.sh:103-111`), System Extensions (only warned about, `lib/uninstall/batch.sh:3297-3314`), Keychain items, login-item BTM database (only detected via launchctl, `lib/uninstall/batch.sh:196-241`), `defaults` domains (preferences are deleted as files only; no `defaults delete` runs, `lib/uninstall/batch.sh:3058-3059` comment).

### 2.3 How matching avoids false positives

1. Bundle id used only if `^[A-Za-z0-9][-A-Za-z0-9]*(\.[A-Za-z0-9][-A-Za-z0-9]*)+$` and not `unknown`; globs/slashes never reach `find -name` (`lib/core/base.sh:1138-1143`, tests "find_app_files rejects bundle ids with glob metacharacters").
2. Boundary match: name equals id or starts with `id.`; "has boundary" also allows `*.id` and `*.id.*` (`lib/core/base.sh:1153-1170`). `com.foo` never matches `com.foobar`.
3. Never delete the roots: a match that ends in Application Support, Caches, Logs, Preferences, ByHost, Containers, WebKit, HTTPStorages, Application Scripts, Autosave Information, Group Containers, `.config`, `.cache`, `.local/share`, or `$HOME` is dropped (`lib/core/app_protection.sh:1583-1603`). Same for `/Library` roots (`lib/core/app_protection.sh:2381-2388`).
4. Shared dot-roots and Steam library roots, and XDG dirs belonging to independent CLIs, are skipped (`lib/core/app_protection.sh:1605-1624`, #993, #1446); top-level dotdirs are never derived from a display name (`lib/core/app_protection.sh:1380-1386`).
5. Generic app names (Music, Notes, Helper, ...) do not drive name-based plist matching (`lib/core/app_protection_data.sh:644-650`).
6. Launch agents/daemons need ownership proof: exact `<id>.plist`, or `Program`/`ProgramArguments.0` that is a regular file physically inside the selected bundle; `com.apple.*` never owned; symlinks rejected (`lib/core/app_protection.sh:857-905`). Rechecked before unload and before delete, with path identity and SHA-256 bound (`lib/uninstall/batch.sh:434-485,908-960`).
7. Sibling guard: if another install with the same bundle id exists (live scan of `/Applications`, `~/Applications`, `/System/Applications`, Input Methods, Setapp apps dir, PlayCover dir, `/opt/homebrew/Caskroom`, `/usr/local/Caskroom`, every `/Volumes` app dir; plus pkg receipts), the plan is narrowed to the selected bundle only: `bundle_id` demoted to `unknown`, no name search, no login item removal, no process kill, no helper bootout, no brew zap (`lib/uninstall/batch.sh:1081-1091,2057-2175`). A partial/unreadable scan counts as "sibling may exist" and keeps shared leftovers with a note (`lib/uninstall/batch.sh:2062-2109`). A surviving sibling with a colliding name keeps only the bundle (`lib/uninstall/batch.sh:2121-2165`).
8. Same checks are repeated immediately before execution against an exact fingerprint of the installation set; a changed app inode/mtime, Info.plist identity, JetBrains selector, or sibling set aborts that app with "select the app again" (`lib/uninstall/batch.sh:1903-1966,2660-2740`).
9. `remove_file_list` re-verifies just before leftover removal: app reappeared at the same path, shared owner, or owner unknown retains the whole leftover family with a labeled reason (`lib/uninstall/batch.sh:770-832`).
10. UUID containers need metadata proof; macOS-managed emptied container stubs are not reported as leftovers; containers holding SIP-protected entries are skipped (needs Full Disk Access to check) (`lib/uninstall/batch.sh:713-768`, `lib/uninstall/batch.sh:3020-3040`).
11. Every path passes `validate_path_for_deletion` and `should_protect_path` in uninstall mode (system-critical components only; data-protected lists are bypassed because the user chose to uninstall) (`lib/uninstall/batch.sh:2326-2335,801-806`, `lib/core/app_protection.sh:406-700`).

### 2.4 Protected and excluded apps

- Hidden entirely from the list: bundle ids matching `SYSTEM_CRITICAL_BUNDLES` (Finder, Dock, Safari, Mail, Settings, Photos, Terminal, ... plus system services and input-method patterns), except `APPLE_UNINSTALLABLE_APPS` (`com.apple.dt.*` Xcode, Final Cut, Motion, Compressor, Logic, GarageBand, iMovie, iWork, MainStage, Server, Playgrounds) (`lib/core/app_protection_data.sh:19-175`, `lib/core/app_protection.sh:143-158`, applied `bin/uninstall.sh:669-671`). Matching is regex from the glob list, case-sensitive.
- Background-only apps (`LSBackgroundOnly`) are hidden unless they sit directly in a search root (`bin/uninstall.sh:632-678`).
- Listed but refused at preview: official-uninstaller vendors (UNINST-14); apps that cannot be handled ("cannot be removed safely by Mole from this location, move it to Trash in Finder"): bundle id refresh failed, identity unreadable, or a sudo removal below a user-mutable ancestor (`lib/uninstall/batch.sh:2000-2035,2220-2232,3425-3436`).
- `/System/Applications` is not a search root, so it is never listed (`bin/uninstall.sh:532-562`).

### 2.5 Running-app handling

Running apps are **not** blocked. Detection by exact `pgrep -x` of `CFBundleExecutable` (shared runtime names like `Electron` are never matched by name) puts the app in `running_apps`, shown as `[Running]` in the confirm prompt (`lib/uninstall/batch.sh:2166-2180,2500-2503`, `lib/core/app_protection.sh` `mole_is_shared_runtime_executable` at `lib/core/base.sh:1147-1151`). After Enter, `force_kill_app` runs: AppleScript `quit` by bundle id (or escaped name) with a 2 s poll, `pkill -x`, `pkill -9 -x`, one `sudo pkill -9 -x` only if `sudo -n true` succeeds, then 3x1 s retries (`lib/core/app_protection.sh:2748-2949`). It refuses `Finder|Dock|loginwindow|WindowServer|SystemUIServer|launchd|coreaudiod|NotificationCenter|ControlCenter|Spotlight` and unsafe patterns (`lib/core/app_protection.sh:2780-2790`). If it survives, uninstall continues, then warns "Still running during uninstall, files removed but process kept alive" (`lib/uninstall/batch.sh:3352-3366`). (Contrast slim, which refuses running apps: 3.2.)

### 2.6 Order of operations per app (execution)

1. Spinner "Uninstalling X...", check app identity unchanged, re-verify sibling set (`lib/uninstall/batch.sh:2656-2740`).
2. `stop_launch_services` (user agents; `/Library` agents/daemons only if system files exist) then `unregister_app_bundle` (`lib/uninstall/batch.sh:2745-2756`).
3. `remove_login_item` by display name (`lib/uninstall/batch.sh:2763-2770`).
4. `force_kill_app` (`lib/uninstall/batch.sh:2780-2792`).
5. Remove the app: Homebrew cask path, or `mole_delete` (sudo if parent unwritable or, in permanent mode, owner differs) (`lib/uninstall/batch.sh:2815-2935`).
6. `remove_file_list` on the reviewed user leftovers (`lib/uninstall/batch.sh:2955-2975`); system list is empty by design.
7. `bootout_login_item_helpers` (`lib/uninstall/batch.sh:3061-3076`).
8. Summary; config-reference hints; background `brew autoremove` if any cask succeeded; Dock + `lsregister -gc` in background (`lib/uninstall/batch.sh:3568-3624`).

Trash batching: with `MOLE_DELETE_MODE=trash`, sudo-free non-symlink paths share one guarded helper that binds physical parent and target identity and renames directly into Trash; app bundles, UUID containers, Containers, Group Containers, Application Scripts and launch agents go per-file through `mole_delete`/`_mole_move_to_trash`, which can fall back to Finder AppleScript `delete` (`lib/uninstall/batch.sh:770-1020`, `lib/core/file_ops.sh:2726-2738,2795-2840`). Finder automation denial (-1743) prints a Privacy & Security hint (`lib/core/file_ops.sh:2812-2820`). Privileged delete under a user-mutable ancestor fails closed (`MOLE_ERR_MUTABLE_PARENT`) (`lib/core/file_ops.sh:2440-2450`).

### 2.7 Homebrew path

Detection `get_brew_cask_name` runs four stages and returns the first hit, in order (`lib/uninstall/brew.sh:479-508`): (1) resolve symlinks and read the token from a `Caskroom` path whose basename equals the app basename; (2) `find` `Caskroom` roots (depth 3) for the exact `.app` name, requires exactly one unique token, listed in `brew list --cask`, and `brew info --cask` must mention the app path (or `/Applications/<name>`), with a symlink-ownership fallback if `info` fails; (3) direct symlink into Caskroom; (4) lowercase app name equals a `brew list --cask` token and `brew info` mentions the path. Failure states are distinct: 0 owned, 1 not, 2 unknown, 124/128+ timeout/signal (a timeout aborts the batch; "unknown" never silently falls back to deleting) (`lib/uninstall/brew.sh:306-466`, `lib/uninstall/batch.sh:2183-2212`). Multi-app batches take one Caskroom/`brew list` snapshot (`lib/uninstall/brew.sh:76-112`, `lib/uninstall/batch.sh:1967-1984`); `--list` prefetches `brew info` in chunks (`lib/uninstall/brew.sh:114-257`).

Uninstall: `brew uninstall --cask <token>` with `HOMEBREW_NO_ENV_HINTS=1 HOMEBREW_NO_AUTO_UPDATE=1 NONINTERACTIVE=1`; **always `nozap`** from the batch path so the cask's zap stanza cannot delete unselected or sibling-shared data (`lib/uninstall/brew.sh:519-618`, call `lib/uninstall/batch.sh:2835-2839`). Timeout 300 s, 600 s if app > 5 GB, 900 s if > 15 GB (`lib/uninstall/brew.sh:548-563`). Success is verified: cask no longer installed and bundle gone. On brew failure, manual removal happens only if the cask is no longer installed (`cask_state==1`) and the app identity is unchanged; otherwise failure reasons "brew uninstall failed, package still installed / state unknown" with a `brew uninstall --cask <token>` hint (`lib/uninstall/batch.sh:2851-2880`). A logged `REMOVED ... brew uninstall <token>` entry is written since Mole's sink did not see the delete (`lib/uninstall/brew.sh:604-607`). After a success, `brew autoremove` runs detached and each removed keg is logged (`lib/uninstall/batch.sh:3391-3403,3596-3606`).

### 2.8 Sudo handling

- Process never starts as root (`bin/uninstall.sh:10-13`).
- Per app, `needs_sudo` = parent directory not writable, OR (permanent mode AND owner is root or another user). In Trash mode, a root-owned app in a user-writable parent does not need sudo (`lib/uninstall/batch.sh:2201-2219`).
- If `needs_sudo` and the app is not a cask, a privileged path-based removal below a user-writable ancestor is rejected at preview (app goes to the "move it in Finder" list) (`lib/uninstall/batch.sh:2220-2232`).
- One sudo session is established after the Enter confirmation and before any removal, when any selected app needs sudo or is a cask; prompt text names the apps ("Admin required for system apps: ..." / "...for Homebrew casks: ...") (`lib/uninstall/batch.sh:2576-2596`). Denied: "Admin access denied", return 1. `ensure_sudo_session` starts a keepalive and stops it at cleanup (`lib/core/sudo.sh:365-396`, `bin/uninstall.sh:1754-1768`, `lib/uninstall/batch.sh:3434-3449`). Failure hints suggest `mole touchid` when Touch ID is not configured (`lib/core/file_ops.sh:4255-4300`).
- System launch plist unload uses `sudo launchctl unload` only if system files exist and not in test mode (`lib/uninstall/batch.sh:462-477,596-615`). System files are never deleted, so no sudo delete of `/Library` paths happens.
- `SUDO_USER` is honored when running brew (`lib/uninstall/brew.sh:572-579`).

## 3. Slim in depth

### 3.1 Universal binary detection (no lipo, no ditto thinning)

Detection and thinning are pure shell with `od`, `tail`, `head`, so the Command Line Tools are not required ("slim runs without developer tools and never calls lipo or xcode-select", `tests/slim.bats:377`; rationale `bin/slim.sh:260-262`).

- Candidate files: `find <app>/Contents -type f` excluding `*/Resources/*` and `*/_CodeSignature/*`, filtered by `file -N` output containing `Mach-O universal` (`bin/slim.sh:392-395`).
- Fat header parse (`slim_fat_slices`, `bin/slim.sh:263-303`): reads first 8 bytes with `od -An -v -tu1`; magic bytes `202 254 186 190` (FAT_MAGIC, 20-byte entries) or `202 254 186 191` (FAT_MAGIC_64, 32-byte entries), big-endian; 1 to 16 archs; every slice must satisfy `offset > 0`, `size > 0`, `offset+size <= file size`. CPU map: `16777228` arm64 (subtype 2 = arm64e), `16777223` x86_64 (subtype 8 = x86_64h), `7` i386, else `other`.
- Thinnable only if exactly one `arm64` slice plus at least one Intel slice (`x86_64`, `x86_64h`, `i386`) and nothing else; **any arm64e slice or other CPU leaves the file alone** (macOS refuses third-party arm64e without the ABI enabled; the app may be running Intel today) (`bin/slim.sh:305-327`, `tests/slim.bats:675`). Intel bytes = sum of Intel slice sizes (`bin/slim.sh:330-334`).
- Thin test: first 8 bytes equal `207 250 237 254 12 0 0 1` (MH_MAGIC_64 + CPU_TYPE_ARM64, little-endian) (`bin/slim.sh:338-340`).

### 3.2 Eligibility and exclusions

App roots: `/Applications` and `~/Applications`, plus one level of plain sub-folders such as `Utilities` (never bundles or symlinked folders) (#1811) (`bin/slim.sh:72-83,410-423`). Skip reasons, checked in this order (`slim_skip_reason`, `bin/slim.sh:137-193`): `whitelisted` (the `~/.config/mole/whitelist` clean whitelist), `symlink`, `not an app bundle`, `App Store app` (`Contents/_MASReceipt`), `not owned by you`, `folder not writable`, `contains files owned by another user` (`find ! -user`), `no bundle identifier`, `Apple app` (`com.apple.*`), `protected app` (system-critical bundle list or official-uninstaller vendor), `set to open using Rosetta` (Finder "Open using Rosetta" stored in `~/Library/Preferences/com.apple.LaunchServices/com.apple.LaunchServices.plist` key `LSArchitecturesForX86_64`), `still running` (`ps -axww -o comm=` prefix match on the bundle path).
Scan-only extra filters: not signed with `Authority=Developer ID Application: ` and a 10-char `[A-Z0-9]` Team ID from `codesign -dv --verbose=2` (`bin/slim.sh:103-111,433-437`); no thinnable files (`bin/slim.sh:438-444`); original rejected by Gatekeeper (`spctl --assess --type execute` exit 3 only; timeout/other answers are kept) assessed in parallel with a 20 s limit (`bin/slim.sh:452-472`). Running apps are listed (tagged `[Running]`) and refused when slimming starts (`bin/slim.sh:136-137,188-191,745-759`, `tests/slim.bats:710`).

### 3.3 Plan, thin, verify, swap

**Plan** (`slim_plan_app`, `bin/slim.sh:358-398`): a file qualifies only if thinning it cannot break a seal. It must live under a sealing root (`Contents/` of an app-like bundle, `Versions/<v>/` of a framework) that has `_CodeSignature/CodeResources` (`bin/slim.sh:232-246`); it must be the bundle's main executable (`CFBundleExecutable`, not listed in its own seal) or be sealed by `cdhash` in `files2` (nested signed code) (`bin/slim.sh:195-258`); and no enclosing bundle may seal the same file as a plain `hash2` file (ScreenFlow QuickLook plugin case) (`bin/slim.sh:376-383`). `CodeResources` is parsed from `plutil -convert xml1` with awk, since `plutil -p` is not parseable (`bin/slim.sh:195-230`). Output is `<relative path>\t<intel bytes>` per file; total is the "reclaimable" size.

**Per-app swap** (`slim_one_app`, `bin/slim.sh:592-715`):
1. Reload whitelist (fail closed if unreadable), recheck skip reasons (including running), and recheck deletion identity `mole_deletion_identity` equals the scan-time identity ("changed since scan") (`bin/slim.sh:600-614`).
2. `codesign --verify --deep --strict <app>` must pass on the original (180 s limit). Only exception: failure text "detritus not allowed" (Finder xattrs) is tolerated (`bin/slim.sh:616-623`).
3. `ditto --clone <app> <stage>/<App>.app` into a `mktemp -d` under the run's work dir (APFS clone, not a thinning tool) (`bin/slim.sh:625-635`).
4. If the original only failed on detritus, strip `com.apple.FinderInfo` and `com.apple.ResourceFork` on the copy only (`xattr -rsd`, not following symlinks) and require the copy to pass strict verify (`bin/slim.sh:637-648`).
5. For each planned file: cut the arm64 slice with `tail -c +offset+1 | head -c size` into `mktemp "<file>.mole-slim.XXXXXX"`, check exact size and thin-arm magic, `chmod` to the original mode, `mv -f` over the file (`slim_thin_file`, `bin/slim.sh:530-555`). SIGPIPE from `tail` is tolerated; the size and magic checks decide.
6. Verify the copy (`slim_verify_copy`, `bin/slim.sh:558-584`): every planned file is thin arm64 ("Apple Silicon code missing"), `codesign --verify --deep --strict` ("code signature check failed"), same Team ID ("signing team changed"), `spctl --assess --type execute` ("Gatekeeper check failed").
7. Reload whitelist again; refuse if now whitelisted or the app started (`bin/slim.sh:665-683`).
8. Swap with INT/TERM deferred until done: `mole_delete` in Trash mode moves the original to Trash, then `mv <copy> <app>` (`bin/slim.sh:685-713`). Failures: "could not move the original to Trash" (copy discarded) or "original is in the Trash, drag it back to <dir>" (copy move failed).

**Codesign implications**: the slimmed app keeps the original Developer ID signature and is not re-signed. Thinning changes the main executable and nested Mach-O files, so this works only because those files carry the bundle/nested signature hashing page-wise per slice and the sealed set excludes plain-hash files. Verification proves the seal still holds; Gatekeeper must still accept. "App updates bring the Intel code back" (`bin/slim.sh:63`, `bin/slim.sh:758`).

**Rollback**: no separate rollback. The original is untouched until step 8 and then goes to the Trash (recoverable), so "rollback" = Put Back from Trash. Copy failures just discard the stage (`slim_discard_stage` only deletes `$SLIM_WORK_DIR/app.*`, `bin/slim.sh:586-590`). The cleanup trap would delete the work dir including the copy, so INT/TERM are held across the swap (`bin/slim.sh:685-707`, `tests/slim.bats:687`).

**Apps are processed sequentially**; the loop breaks only on a timeout/signal return code from `mole_delete` (`bin/slim.sh:903-924`). Freed bytes in the summary are the Intel byte total (not measured disk change, and the originals still sit in Trash).

### 4.3 Exit codes

## 6. Porting notes (subtle or easy to get wrong)

1. **Personal data is kept by default.** Only caches and logs are auto-selected; everything else (Application Support, Preferences, Containers, Group Containers, `.config`, ...) is "personal" and unchecked until the user opts in with `D` or `--with-data`. A naive "delete everything we find" port will violate this (`lib/uninstall/review.sh:72-108`). The `--with-data` holdbacks (Chromium/Firefox/Arc/Zen profiles, Group Containers, CrossOver, Whisky, UTM, VirtualBuddy, OpenEmu, emulators, Minecraft launchers) must be case-insensitive (APFS) (`lib/uninstall/review.sh:28-69`).
2. **Cache-resident user data**: Spotify offline music, Raycast clipboard images, Mullvad Browser profile, Buzz models live under `Caches` but are personal (`lib/uninstall/review.sh:6-12`).
3. **System-level leftovers are never deleted.** `/Library` and receipt matches are shown "Review only" and the plan blanks them before execution (`lib/uninstall/batch.sh:2336-2346`). The comment warns not to remove the blanking.
4. **Trash is not "freed".** Summary must not claim freed space in Trash mode (`lib/uninstall/batch.sh:3243-3251`). Slim still reports Intel bytes as "freed" despite originals in Trash.
5. **Match on the current bundle basename, not the cached display name** (`lib/uninstall/batch.sh:2024-2028`). Display names are only for UI and are sanitized for control bytes at render sites only, never in matching (`lib/ui/app_selector.sh:12-16`).
6. **Same-bundle-id siblings** (Xcode/Xcode-beta, iTerm2/iTerm2-beta, Zed channels, `Foo.app` vs `Foo-beta.app`): demote bundle id and name matching, skip login items, kill, helper bootout, toolchain heuristics, diagnostic reports, and brew zap. A scan that cannot prove absence must behave as "sibling exists" (#1339, #1340, #1624) (`lib/uninstall/batch.sh:2057-2175`). The id compare is case-insensitive (`lib/uninstall/batch.sh:1028-1037`).
7. **Time-of-check/time-of-use**: preview is bound to inode+mtime of the app and `Info.plist`, to the sibling-install fingerprint, to launch-plist SHA-256 and physical path identity, and to a JetBrains selector. Execution must recheck at every side effect and demote on mismatch (`lib/uninstall/batch.sh:1903-1966,434-485`).
8. **Reverse-DNS validation** before any bundle id enters a `find -name` or path; malformed Info.plist ids must not widen matches (`lib/core/base.sh:1138-1143`). Boundary matching at `.` only.
9. **`pgrep`/`pkill` patterns are regexes**: escape `CFBundleExecutable` literally, reject control chars and empty strings (empty matches every process), never match shared runtime names (Electron), refuse system process names (`lib/core/app_protection.sh:2714-2735,2780-2832`).
10. **Running apps are killed after confirmation** (quit, TERM, KILL), with only a `[Running]` tag as warning; contrast slim, which refuses running apps. A port may want an explicit "quit first" step (the kill ladder is aggressive and loses unsaved work).
11. **Homebrew**: never pass `--zap`; use nozap always in batch. Distinguish "not installed" from "could not determine" from "timed out"; only fall back to manual removal when brew positively says the cask is gone. Cask tokens do not appear in the matching code path for CLI names (see 4.4).
12. **Launch agent unload needs ownership** (exact id file or program inside the bundle). Do not match agents by display-name substring alone; <5-char or common names are excluded (`lib/core/app_protection_data.sh:644-650`).
13. **UUID containers** have no readable app identity; verify `MCMMetadataIdentifier`. Treat emptied container stubs as non-leftovers; containers may need Full Disk Access to inspect, and without FDA container sizes are not measured at all (`lib/core/file_ops.sh:4217-4226`). Moving `~/Library/Containers` entries to Trash needs direct handling (no third-party Trash helper), and the TCC/Privacy denial path needs a Finder fallback and a user-facing hint.
14. **SIP-protected content inside containers** makes Empty Trash fail later; scan with `/usr/bin/find -flags +restricted -o -flags +sunlnk -o -xattrname com.apple.rootless` (the system `find`, not a GNU one) and skip such containers (`lib/uninstall/batch.sh:730-768`).
15. **Confirmation must require a real terminal**: a closed/non-TTY stdin must not count as Enter. Same for slim's confirm (`lib/uninstall/batch.sh:2510-2548`, `bin/slim.sh:765-769`). Drain keystrokes typed during scans (#726).
16. **Display-name resolution order** matters and is easy to get wrong: localized `InfoPlist.strings` for the first preferred language the bundle actually localizes (do not fall through to a language the user did not ask for), then Spotlight name (reject paths and dot-names), then plist names. Keep versioned bundle names when metadata collapses them (`bin/uninstall.sh:125-305`).
17. **Size/last-used**: Spotlight `kMDItemLastUsedDate`/`PhysicalSize` can be null for new or unindexed apps; fall back to bundle mtime and a bounded `du`. Decimal units (1000-based), 30-day months. Epoch before 2001 is treated as unknown.
18. **Hidden/staging apps**: prune hidden folders (updater staging) but keep hidden `.app` bundles; prefer visible apps over hidden duplicates with the same id (`bin/uninstall.sh:757`, `1199-1201`). Skip apps nested in other apps, symlinks to system locations, PlayCover launcher aliases.
19. **Direct-name matching**: exact (display or `.app` basename) wins and stops that term; substring only if no exact; multi-word args are first tried joined as one name unless every word is itself an exact app name (`bin/uninstall.sh:1819-1857`). Escape glob chars in the term.
20. **pkgutil receipts are expensive** (per-package `--files`); cache keyed by the receipt list plus receipt plist mtimes; a complete/provable answer is needed for sibling detection, a best-effort one is fine for discovery (`lib/core/pkg_receipts.sh:12-234`).
21. **Slim file selection is subtle**: only the main executable or `cdhash`-sealed nested code; never a plain-hash-sealed file, even when its own nested bundle is signed (ScreenFlow) (`bin/slim.sh:366-387`). Parse the fat header yourself (FAT_MAGIC 32-bit vs FAT_MAGIC_64, big-endian) and validate slice bounds; keep arm64e files untouched; require exactly one arm64 slice.
22. **Slim copy semantics**: `ditto --clone` (APFS clone) copy, thin on the copy, verify with strict deep codesign, same Team ID, and Gatekeeper, then swap. The original's pre-existing detritus (Finder xattrs) is the only tolerated signature problem and is cleaned on the copy only. Thinning must create its output exclusively (mktemp beside the file), never write through an existing suffix symlink (`bin/slim.sh:530-555`, `tests/slim.bats:794`).
23. **Slim swap is not atomic.** Original is moved to Trash and then the copy is renamed into place; a failure between them leaves the app in Trash only (message tells user to drag it back). Hold signals across the swap and make the cleanup trap not delete the copy until the rename is done (`bin/slim.sh:685-713`).
24. **Slim detection of Apple Silicon**: use the sysctl `hw.optional.arm64` (absolute path), not `uname -m` (Rosetta shells report x86_64) (`bin/slim.sh:90-92`, #1804).
25. **Slim excludes** App Store apps, Apple apps, Rosetta-preference apps, apps not owned by the user, apps with any file owned by another user, symlinked apps, non-Developer-ID signed apps, apps Gatekeeper already rejects, and apps on the clean whitelist (whitelist reloaded at plan time and again just before swap, fail-closed).
26. **Exit-code mismatch**: slim defines exit 4 for unsupported host but returns 1 (`bin/slim.sh:35,864`). Choose deliberately in a port.
27. **Never edit user config files**; only report references by file:line, and only for configuration paths that no longer exist after a non-dry run (`lib/uninstall/config_refs.sh:70-84`).
28. **AppleScript use** (login item deletion, quit, Finder delete) needs Automation permission, can hang on a permission dialog; every call is wrapped in a timeout and treated as best effort. `sfltool dumpbtm` is avoided because it raises an admin password dialog (`lib/uninstall/batch.sh:190-195`).
29. **README cross-check**: `--with-data`, `D`, Trash default, Slim exclusions and "needs no developer tools" all match the code (`README.md:158,226,473`). **[DOC-ONLY]**: none found for these two commands. Absent features a port might assume: `--json`, `--yes`, `--app`, select-all in the app selector, per-command shell completion, `--whitelist` for uninstall.
30. **Test surface** (for porting parity): `tests/uninstall*.bats` (222 + 14 + 41 + 4 + 35 + 21 + 61 + 35 + 12 + 4 + 3 tests across uninstall, menu, naming variants, process pattern, remove_file_list, review, safety, bash32 scan, steam launcher, timeout, tty foreground), `tests/brew_uninstall.bats` (31), `tests/slim.bats` (33), PTY drivers `tests/uninstall_menu_pty.py`, `tests/uninstall_review_pty.py`, `tests/uninstall_brew_output_pty.py`, `tests/menu_search_pty.py`.
